# Default Constructor in C++

This example demonstrates the concept of a **default constructor provided implicitly by the compiler** when no constructor is explicitly declared in a class.

The example covers:

* Class and object
* Attributes
* Compiler-provided default constructor
* Default construction of data members
* `string` vs `int` initialization
* Setter and getter methods
* Object creation without arguments

---

# 1. Code

```cpp
#include <bits/stdc++.h>
using namespace std;

class Employee {
private:
    string name;
    int empID;

public:

    // No constructor is explicitly defined in this class.
    //
    // Therefore, if we don't declare any constructor,
    // the compiler implicitly declares a default constructor.
    //
    // Employee emp1;
    //        ↓
    // Compiler-provided default constructor
    //
    // The compiler-generated constructor performs default
    // construction of the data members.
    //
    // name  → string is default-constructed to an empty string
    // empID → int is NOT automatically initialized to 0
    //
    // For a local object, empID has an indeterminate value
    // until we explicitly assign a value to it.


    // Setter method
    // Used to assign values to the private attributes.
    void setEmployee(string name, int empID) {
        this->name = name;
        this->empID = empID;
    }


    // Getter method
    // Used to display the private attributes.
    void getEmployee() {
        cout << "Employee name : " << name << endl;
        cout << "Employee ID : " << empID << endl;
    }
};

int main() {

    // No constructor is explicitly defined in Employee.
    //
    // Therefore, the compiler provides a default constructor.
    //
    // This constructor is automatically called when emp1
    // is created.
    Employee emp1;

    // Assign values to the object's attributes.
    emp1.setEmployee("Suresh", 202232);

    // Display employee information.
    emp1.getEmployee();

    return 0;
}
```

---

# 2. What is a Default Constructor?

A **default constructor** is a constructor that can be called without providing any arguments.

For example:

```cpp
Employee emp1;
```

does not provide any arguments.

Therefore, an `Employee` object must be constructed using a constructor that requires no arguments.

---

# 3. Compiler-Provided Default Constructor

In this class:

```cpp
class Employee {
private:
    string name;
    int empID;

public:

    // No constructor
};
```

we have **not explicitly declared any constructor**.

When no constructor is declared, the compiler implicitly declares a default constructor for the class.

Conceptually:

```text
Employee class
      ↓
No constructor declared
      ↓
Compiler provides default constructor
      ↓
Employee emp1;
      ↓
Default constructor is called
```

The constructor is not visible in your source code because it is **implicitly generated by the compiler**.

---

# 4. Object Creation

In `main()`:

```cpp
Employee emp1;
```

This creates an `Employee` object.

Since no constructor was explicitly declared, the compiler-generated default constructor is used.

Conceptually:

```text
Employee emp1
      ↓
Compiler-generated default constructor
      ↓
Data members are default-constructed
```

---

# 5. What Happens to the Attributes?

The class contains:

```cpp
string name;
int empID;
```

The compiler-generated default constructor performs **default initialization/default construction** of the members.

However, the behavior depends on the type of the member.

### `string name`

`std::string` is a class type.

Its default constructor is called:

```cpp
string name;
```

The resulting string is empty:

```text
name = ""
```

### `int empID`

`int` is a fundamental type.

The compiler-generated default constructor does **not** initialize it to `0` for an ordinary automatic object.

Therefore:

```text
empID = indeterminate value
```

until we explicitly assign a value.

---

# 6. Why Does the Program Still Work?

After creating the object:

```cpp
Employee emp1;
```

we immediately call:

```cpp
emp1.setEmployee("Suresh", 202232);
```

The setter assigns values:

```cpp
this->name = name;
this->empID = empID;
```

Therefore, before we read the values, both attributes have valid assigned values.

The final state becomes:

```text
Employee emp1
│
├── name  = "Suresh"
└── empID = 202232
```

Then:

```cpp
emp1.getEmployee();
```

prints the values.

---

# 7. Setter Method

The class contains:

```cpp
void setEmployee(string name, int empID) {
    this->name = name;
    this->empID = empID;
}
```

This method is used to assign values to the private attributes.

When we call:

```cpp
emp1.setEmployee("Suresh", 202232);
```

the values are assigned:

```text
name  → "Suresh"
empID → 202232
```

---

# 8. `this` Pointer

Inside the setter:

```cpp
this->name = name;
this->empID = empID;
```

There are two different `name` identifiers:

```cpp
void setEmployee(string name, int empID)
```

Here `name` and `empID` are **parameters**.

Whereas:

```cpp
this->name
this->empID
```

refer to the attributes belonging to the current object.

Therefore:

```cpp
this->name = name;
```

means:

```text
object's name = parameter name
```

and:

```cpp
this->empID = empID;
```

means:

```text
object's empID = parameter empID
```

---

# 9. Getter Method

The getter/display method is:

```cpp
void getEmployee() {
    cout << "Employee name : " << name << endl;
    cout << "Employee ID : " << empID << endl;
}
```

It accesses the private attributes from inside the class and displays them.

The object calls it using:

```cpp
emp1.getEmployee();
```

Output:

```text
Employee name : Suresh
Employee ID : 202232
```

# 10. Complete Execution Flow

The program executes in this order:

```text
Employee emp1;
       ↓
No constructor explicitly declared
       ↓
Compiler-provided default constructor
       ↓
Employee object created
       ↓
setEmployee("Suresh", 202232)
       ↓
Attributes receive values
       ↓

       ↓
Employee details displayed
```

# 11. Compiler-Provided vs User-Defined Default Constructor

There are two different situations.

## Compiler-Provided

You don't write any constructor:

```cpp
class Employee {
private:
    string name;
    int empID;
};
```

The compiler provides a default constructor.

Then:

```cpp
Employee emp1;
```

works.

---

## User-Defined

You explicitly write a constructor:

```cpp
class Employee {
public:

    Employee() {
        name = "Unknown";
        empID = 0;
    }
};
```

Now the constructor is written by the programmer.

```cpp
Employee emp1;
```

calls your constructor.

### Comparison

|                                           | Compiler-Provided | User-Defined                         |
| ----------------------------------------- | ----------------- | ------------------------------------ |
| Constructor written by programmer         | ❌                 | ✅                                    |
| Can initialize members with custom values | ❌                 | ✅                                    |
| Called automatically                      | ✅                 | ✅                                    |
| Takes no arguments                        | Yes               | Can be designed to take no arguments |
| Example                                   | `Employee emp1;`  | `Employee emp1;`                     |

---

# 12. Important Rule

The compiler provides a default constructor **only when the class does not have a user-declared constructor**.

For example:

```cpp
class Employee {
public:
    Employee(string name) {
        // ...
    }
};
```

Now we have declared a constructor.

The compiler will **not additionally provide a no-argument default constructor** for us.

Therefore:

```cpp
Employee emp1;   // ❌ No matching default constructor
```

would be invalid.

You would need:

```cpp
Employee emp1("Suresh");
```

or explicitly provide a default constructor as well.

---

# 13. Important Initialization Detail

Do not confuse:

```text
Default constructor
```

with:

```text
All attributes are initialized to default values such as 0
```

For example:

```cpp
class Employee {
private:
    string name;
    int empID;
};
```

When:

```cpp
Employee emp1;
```

is created:

```text
name  → empty string
empID → indeterminate value
```

`empID` is **not automatically guaranteed to be `0`** merely because the compiler generated the default constructor.

However, in this program:

```cpp
emp1.setEmployee("Suresh", 202232);
```

assigns `empID` before it is read.

---

# 14. Key Takeaways

### Default Constructor

A constructor that can be called without arguments.

```cpp
Employee emp1;
```

### Compiler-Provided Default Constructor

If no constructor is declared in the class, the compiler can implicitly declare a default constructor.

```text
No constructor declared
        ↓
Compiler provides default constructor
        ↓
Employee emp1;
```

### `string`

A `string` member is default-constructed into an empty string.

### Fundamental Types

Members such as:

```cpp
int
float
char
```

are not automatically initialized to zero merely because the compiler generated the default constructor.

### Setter

Used to assign values:

```cpp
emp1.setEmployee("Suresh", 202232);
```

### Getter

Used to access/display values:

```cpp
emp1.getEmployee();
```

---

# 15. Interview Definition

> **A default constructor is a constructor that can be called without arguments. If a class has no user-declared constructor, the compiler can implicitly provide a default constructor. The compiler-generated constructor performs default initialization of the class's data members according to their types.**
